# MemoryStore 项目设计文档

> 版本：v0.7  
> 日期：2026-09-04  
> 状态：功能闭环（已纳入基础设施与产品决策）

---

## 1. 项目概述

### 1.1 背景

手机本地存储有限，拍摄的照片与视频占用空间大。不使用 iCloud，希望照片数据完全私有、可控。需要一套「手机拍摄 → 自家设备存储 → 可选择性分享」的私有相册方案。

### 1.2 产品定位

**MemoryStore** 是一套私有媒体库：

| 端 | 定位 |
|----|------|
| **iOS App** | 账号登录、自动扫描、Wi‑Fi 增量上传、列表角标展示本地/远端状态、按需下载与大图浏览；**手动**清理本机已备份原片 |
| **Server** | 运行在家中 iMac：多用户账号、上传接收、按用户隔离存储、元数据、缩略图、分享鉴权 |
| **H5** | 面向受邀访客的只读在线浏览页（不依赖访客账号） |

### 1.3 已确认决策

| 决策项 | 结论 |
|--------|------|
| 客户端 | 首期 **仅 iOS** |
| 本机原片 | 上传成功后**保留本地**，标记为「已备份」；仅在用户编辑多选确认后才删除系统相册原片 |
| 列表角标 | 三态：待上传 / 已备份（本地+远端）/ 可下载（仅远端） |
| 基础设施 | **公网云服务器** + **家中 iMac**，二者已通过 **FRP** 打通 |
| 数据落盘 | 原片与元数据落在 **iMac**，云服务器不做主存储 |
| 自动上传网络 | **Wi‑Fi 下**自动上传（蜂窝默认关闭） |
| 账号体系 | **支持多用户**；用户间媒体数据隔离 |
| 登录方式（前期） | **简单登录**：用户名/密码（或邮箱/密码）注册与登录 |
| 登录方式（后期） | **手机号 + 短信验证码**登录（预留接口与数据模型） |

### 1.4 核心原则

| 原则 | 说明 |
|------|------|
| 私有优先 | 媒体文件落盘在家中 iMac；云机仅作公网入口与反向代理 |
| 用户隔离 | 每个账号拥有独立媒体库；默认互不可见 |
| 增量自动 | Wi‑Fi 下自动发现新增媒体并上传 |
| 空间回收 | 编辑模式可删本机已备份原片；也可筛选「仅云端」永久删除服务端副本（文件+库） |
| 分享可控 | H5 基于令牌，可过期、可撤销 |
| 端侧闭环 | App / Server / H5 职责清晰，三端协作无断点 |

## 2. 系统架构

### 2.1 基础设施拓扑（FRP）

已有条件：云服务器具备公网 IP；iMac 在家运行；二者 FRP 已打通。

```
                         公网
┌──────────────┐        HTTPS         ┌─────────────────────────┐
│  iPhone App  │ ───────────────────► │   云服务器 (公网 IP)     │
│  / 访客 H5   │                      │  - Nginx / Caddy        │
└──────────────┘                      │  - TLS 证书             │
                                      │  - frps (FRP Server)    │
                                      └───────────┬─────────────┘
                                                  │ FRP 隧道
                                                  │ (已打通)
                                      ┌───────────▼─────────────┐
                                      │   家中 iMac             │
                                      │  - frpc (FRP Client)    │
                                      │  - MemoryStore Server   │
                                      │  - 原片 / 缩略图 / DB   │
                                      └─────────────────────────┘
```

**职责拆分：**

| 机器 | 职责 | 不负责 |
|------|------|--------|
| 云服务器 | 公网入口、TLS 终结、反向代理到 FRP 隧道、可选限流/WAF | 不存原片、不做业务数据库主库 |
| iMac | MemoryStore 业务服务、文件存储、缩略图、元数据库 | 不直接暴露公网端口（经 FRP 出网） |

### 2.2 访问路径

| 场景 | 路径 | 说明 |
|------|------|------|
| App 上传 / 浏览 / 下载 | App → 云服务器域名 → FRP → iMac Server | 统一走公网域名，实现简单 |
| H5 访客浏览 | 浏览器 → 同域名 → FRP → iMac | 与 App 共用入口，权限靠 shareToken 隔离 |
| （可选优化）在家直连 | App 检测家庭局域网 IP，直连 iMac | 大文件上传更快；首期可不做，统一走 FRP |

**首期建议：** App 与 H5 统一配置一个公网域名（指向云服务器），全部经 FRP 到 iMac，降低双通道复杂度。M3 再考虑「在家局域网直连加速」。

### 2.3 逻辑分层

```
┌────────────────────────────────────────────────────────────┐
│ 表现层：iOS App UI / H5 Gallery UI                         │
├────────────────────────────────────────────────────────────┤
│ 应用层：账号认证 / 同步引擎 / 浏览 / 分享 / 删片策略         │
├────────────────────────────────────────────────────────────┤
│ 领域层：User / Session / Media / Device / ShareLink / …    │
├────────────────────────────────────────────────────────────┤
│ 基础设施：iMac 磁盘 / SQLite / 任务队列 / FRP / 反向代理    │
└────────────────────────────────────────────────────────────┘
```

### 2.4 部署形态（首期）

| 组件 | 部署位置 | 说明 |
|------|----------|------|
| frps + Nginx/Caddy | 云服务器 | 公网 443；反代到 FRP 本地映射端口 |
| frpc | iMac | 将本机 MemoryStore 端口映射到云端 |
| MemoryStore Server | iMac | API + 静态 H5 + 异步缩略图任务 |
| 存储目录 | iMac 磁盘 / 外挂盘 | 原片权威存储 |
| iOS App | iPhone | 仅 Wi‑Fi 自动上传；经域名访问服务 |

## 3. 端侧功能闭环

### 3.1 iOS App（用户端）

#### 3.1.1 职责

用户在手机上的入口：账号登录 → 发现媒体 → Wi‑Fi 上传到**当前用户**媒体库 → **标记已备份（保留本机）** → 时间轴角标展示三态 → 编辑模式下可手动删除本机已备份原片 → 按需再下载。

#### 3.1.2 功能清单

| 模块 | 功能 | 优先级 |
|------|------|--------|
| **账号登录（前期）** | 注册 / 登录；Token 存 Keychain | P0 |
| **账号登录（后期）** | 手机号验证码登录 | P2 |
| 权限与引导 | 照片库读写；说明「自动备份，手动清理本机」 | P0 |
| 媒体扫描 / 增量 | Photos 索引与变更监听 | P0 |
| 自动上传 | Wi‑Fi 下队列上传 | P0 |
| 校验确认 | complete 成功后标记已备份，**不自动删本地** | P0 |
| **列表角标** | 待上传 / 已备份 / 可下载（仅远端）三态 | P0 |
| **编辑模式** | 多选；过滤「已备份」/「已备份且 >30MB」/「仅云端」 | P0 |
| **大文件清理** | 编辑态筛选已备份且超过 30MB 的项，支持一键删除本机原片 | P0 |
| **仅云端删除** | 过滤仅远端项；确认后永久删除服务端原片与派生文件及 DB 记录 | P0 |
| **下载回本地** | 「可下载」项可保存回系统相册 → 状态回「已备份」 | P0 |
| 时间轴 / 大图 | 统一展示本地+远端 | P0 |
| **大图展示样式** | 设置中选择：边框模式 / 水印杂志模式；展示时间·地点·相机 EXIF；故事优先 | P0 |
| **照片故事** | 手动填写或 AI 生成；存服务端；大图优先展示故事 | P0 |
| 网络策略 | 仅 Wi‑Fi 自动上传 | P0 |
| 设备登记 | 登录后登记设备 | P0 |
| 状态面板 | 待上传、已备份、仅远端、失败 | P1 |

#### 3.1.3 关键流程：自动备份（保留本地）

```
新照片 → 扫描 → pending（角标=待上传）
    → Wi‑Fi 上传 → Server 校验成功
    → status=backed_up（角标=已备份，本地原片保留）
```

#### 3.1.4 关键流程：编辑清理本机

```
编辑 → 过滤「已备份」或「已备份且 >30MB」
    → 多选 / 一键全选过滤结果 → 确认删除本机
    → 仅删已有 remoteMediaId 的 PHAsset
    → status=remote_only（角标=可下载）

编辑 → 过滤「仅云端」
    → 多选 → 确认永久删除云端
    → Server 删除 originals + derivatives + media 行
    → 本地索引移除；时间轴不再展示
```

**大文件阈值（首期）：** 30 MiB（`30 * 1024 * 1024` 字节）。尺寸取本地同步索引 `byte_size`，若缺失则用服务端 `size_bytes`。

**硬约束（云端删除）：** 仅 `remote_only`（本地无 PHAsset、远端有 media_id）可走云端删除；`backed_up` 须先删本机或不得直接删云端（避免误删唯一副本时本地仍指向已失效远端——首期禁止对已备份项删云端）。

#### 3.1.5 角标三态

| 状态 | 含义 | 角标 |
|------|------|------|
| 待上传 | 本地有、远端无 | 待上传图标 |
| 已备份 | 本地有、远端有 | 已备份图标 |
| 可下载 | 本地无、远端有 | 下载到本地图标 |

**硬约束：** 未备份成功（无 remoteMediaId）的项，编辑模式不得删除本机原片。

#### 3.1.6 与 Server 交接

| App → Server | Server → App |
|--------------|--------------|
| 登录；上传；分享；下载原图；删云端；更新故事 | token、mediaId、缩略图、列表、manifest、故事文案 |
| 删本地不调用 Server | — |

#### 3.1.7 大图展示样式与故事

设置页可选两种大图样式（本地偏好，不写服务端）：

| 样式 | 视觉 | 信息层 |
|------|------|--------|
| **边框模式** | 当前图高斯模糊铺底；主图圆角悬浮+阴影；浅色/深色协调 | 主图下方：时间、地点、相机 EXIF；有故事则优先展示故事 |
| **水印杂志模式** | 浅色画布；大图完整展示；标题/日期/地点偏艺术排版 | 文案压在图上（渐变可读性）；故事优先于纯 EXIF 叙述 |

元数据来源：

1. **故事 / 标题 / 地点文案**：服务端字段（可编辑）。有故事时大图优先展示故事。  
2. **拍摄时间 / 相机 EXIF / GPS**：客户端从原片读取；服务端可冗余 `taken_at`。  

故事支持：手动编辑；`POST .../story/ai` 生成草稿后用户确认保存。

### 3.2 Server（iMac 业务服务端）

#### 3.2.1 职责

私有媒体库的权威端：多用户账号与会话、鉴权、可靠入库、**按用户隔离**的元数据与文件、派生文件、分享控制。经 FRP 对外提供服务。

#### 3.2.2 功能清单

| 模块 | 功能 | 优先级 |
|------|------|--------|
| **用户账号（前期）** | 注册、登录、登出、刷新 Token；密码安全存储（argon2/bcrypt） | P0 |
| **用户账号（后期）** | 手机号绑定、短信验证码登录；验证码限流与防刷 | P2 |
| **注册管控** | 可选邀请码 / 关闭公开注册，避免公网乱注册 | P0 |
| 设备登记 | 登录用户下登记/吊销设备；用于同步状态，非主鉴权凭证 | P0 |
| 用户鉴权 | Bearer access_token；所有读写 API 绑定 `user_id` | P0 |
| 上传 API | init / chunk / complete；**同一用户内**同 hash 秒传 | P0 |
| 存储引擎 | 按用户分目录原子写入 | P0 |
| 完整性 | complete 时强制校验 size + hash，失败不入库 | P0 |
| 元数据 | 归属 user_id；类型、尺寸、时长、takenAt、hash、路径、来源设备 | P0 |
| 缩略图 | 异步生成 thumb_sm / thumb_md | P0 |
| 浏览 / 下载 API | 仅返回当前用户媒体 | P0 |
| 对账 API | 当前用户 manifest | P0 |
| 分享服务 | 创建 / 撤销 / 过期；归属创建者用户 | P0 |
| 访客鉴权 | shareToken 只读；禁止写与越权列举 | P0 |
| 健康检查 | `/health` 供云端探活 | P0 |
| 存储监控 | 全局或按用户占用（P1） | P1 |
| 视频预览转码 | 首期原片 + 封面即可 | P2 |

#### 3.2.3 关键流程：账号登录（前期）

```
App: POST /auth/register { username, password }  （若开启公开注册或持有邀请码）
  → Server 创建 user，返回需登录

App: POST /auth/login { username, password }
  → Server 校验密码
  → 签发 access_token（+ 可选 refresh_token）
  → App 存 Keychain，后续请求带 Bearer

App: POST /devices/register { name, model, … }
  → 在当前 user 下登记设备，便于多端同步摘要
```

后期手机号登录（预留）：

```
App: POST /auth/sms/send { phone }
  → Server 调短信通道，存验证码（短 TTL）
App: POST /auth/sms/login { phone, code }
  → 校验通过则登录或自动建号，签发同一套 Token
```

#### 3.2.4 关键流程：上传入库

```
App: POST /upload/init { hash, size, takenAt, ... }   // 已登录
Server:
  在当前 user_id 下若 hash 已存在 → 秒传返回 mediaId
  否则 → uploadId + 临时目录
App: PUT chunks
Server: complete
  → 校验 size + hash
  → 失败：删除临时文件，返回错误（App 不删本地）
  → 成功：移入 originals/{userId}/…，写 DB（带 user_id），投递缩略图，返回 mediaId
```

#### 3.2.5 关键流程：H5 分享

```
用户在 App 创建分享 → Server 生成 shareToken（归属该 user + 范围 + 过期）
访客打开 H5（公网域名）
  → 经云服务器 FRP 到 iMac
  → 校验 token
  → 只读返回范围内媒体
  → 拒绝上传/删除/越权列举
```

#### 3.2.6 与云服务器的边界

| iMac Server | 云服务器 |
|-------------|---------|
| 全部业务 API、文件、DB、账号 | TLS、反向代理、FRP 服务端 |
| 业务限流（按 user / IP） | 可选 IP 限流 / fail2ban |
| 日志与审计 | 仅访问日志（勿记录文件正文） |

### 3.3 H5（访客只读端）

#### 3.3.1 职责

无需安装 App，凭分享链接在线浏览；只读、范围受控、可撤销。

#### 3.3.2 功能清单

| 模块 | 功能 | 优先级 |
|------|------|--------|
| 令牌进入 | URL 带 shareToken；无效/过期提示 | P0 |
| 相册墙 | 缩略图网格 / 简单时间分组 | P0 |
| 大图浏览 | 滑动、缩放 | P0 |
| 视频播放 | 原生 video（原片或后续预览流） | P1 |
| 下载控制 | 默认关，或分享时配置允许 | P1 |
| 二级口令 | 可选 | P1 |
| 响应式 | 手机浏览器优先 | P0 |

#### 3.3.3 关键流程

```
用户发链接 → 访客打开 → 校验 token → 列表/大图 → 到期或撤销即失效
```

#### 3.3.4 首期不做

- 访客上传、评论、点赞  
- SEO 公开收录  
- 无令牌广场

### 3.4 云服务器（网关，非业务端）

虽不是「业务三端」之一，但是闭环基础设施，职责如下：

| 能力 | 说明 |
|------|------|
| frps | 维持与家中 iMac 的隧道 |
| 反向代理 | `https://memory.example.com` → FRP 映射的本地端口 |
| TLS | Let’s Encrypt 等证书终结 |
| 探活 | 定期检测上游 `/health`，隧道断开时返回友好 502 页 |

**明确：** 云盘不落原片；隧道中断时上传/浏览不可用，App 应保留 pending 队列待恢复。

## 4. 跨端闭环场景

### 场景 A：日常自动备份（主路径）

1. 用户登录 → Wi‑Fi 下扫描上传  
2. Server 校验入库  
3. App **标记已备份，保留本机原片**；角标=已备份  

### 场景 B：手动清理本机后再看 / 再下

1. 编辑 → 过滤已备份 → 多选 → 删除本机原片  
2. 角标变为「可下载」；大图仍从 Server 加载  
3. 用户可「保存到相册」，状态回到已备份  

### 场景 C：分享给朋友

1. 用户创建分享链接  
2. 朋友 H5 只读浏览  

### 场景 D：FRP 中断

1. 上传失败保留 pending，不改本机  
2. 隧道恢复后续传  

### 场景 E：换机 / 重装

1. 同账号登录；manifest 对账  
2. 本地未备份继续传；仅远端项显示「可下载」  

### 场景 F：多用户隔离

1. A/B 各自库互不可见（未分享时）

## 5. 领域模型（简要）

### 5.1 核心实体

| 实体 | 关键字段 | 说明 |
|------|----------|------|
| User | id, username, passwordHash, phone?, status, createdAt | 账号主体 |
| Session | id, userId, tokenHash, refreshHash?, expiresAt | 登录会话 |
| Device | id, userId, name, lastSeenAt, revokedAt | 归属用户的设备登记 |
| Media | id, userId, hash, type, size, takenAt, path, status | 权威媒体（按用户隔离） |
| MediaDerivative | mediaId, kind, path | 缩略图等 |
| Album | id, userId, title, coverMediaId | 逻辑相册（可后置） |
| AlbumMedia | albumId, mediaId, sort | 成员 |
| ShareLink | id, userId, tokenHash, scope, expiresAt, passwordHash?, revokedAt | 分享 |
| SyncState | userId, deviceId, lastScanAt, pendingCount | 设备同步摘要 |

### 5.2 客户端媒体状态机

```
discovered → pending_upload → uploading → backed_up ──(用户编辑删本地)──► remote_only
                 ↑                │              │                              │
                 └──── failed ────┘              │                    (保存回相册)
                                                 └──────────────────────────────┘
```

**规则：**

- 上传/秒传成功 → `backed_up`（本地+远端），**不自动删本地**  
- 仅用户在编辑模式确认后 → `remote_only`  
- `remote_only` 保存回相册成功 → `backed_up`  
- 无 `remoteMediaId` 禁止删本机  

服务端：`receiving → stored → derivatives_ready`。

## 6. API 草案（闭环最小集）

> 前缀：`/api/v1`  
> App：`Authorization: Bearer <access_token>`（用户会话）  
> H5：`X-Share-Token: <share_token>`

### 6.1 账号与设备（前期）

- `POST /auth/register` — 用户名+密码注册（可要求邀请码）

## 7. 存储与安全

### 7.1 iMac 文件布局（示例）

```
/Volumes/MemoryStore/
  originals/{userId}/2026/09/04/{mediaId}_{shortHash}.jpg
  derivatives/{userId}/thumb_sm/{mediaId}.jpg
  derivatives/{userId}/thumb_md/{mediaId}.jpg
  tmp/uploads/{userId}/{uploadId}/
  db/
```

### 7.2 安全要点

| 项 | 方案 |
|----|------|
| 传输 | 云服务器强制 HTTPS；FRP 隧道建议加密 |
| 用户身份 | access_token 仅存哈希；可登出作废 |
| 密码 | argon2id / bcrypt；禁止明文日志 |
| 用户隔离 | 所有媒体查询强制 `user_id = 当前用户`；禁止跨用户 IDOR |
| 注册管控 | 公网部署建议邀请码或关闭开放注册 |
| 设备 | 从属于用户；可吊销单设备，不影响账号本身 |
| 分享 | 高熵 token；过期；撤销；可选口令；最小范围 |
| 私有性 | 无令牌不可列举；H5 不可越权 |
| 完整性 | complete 必须校验 size + hash；失败不删手机原片 |
| 云机 | 不落原片；代理超时与上传体积限制合理配置 |
| 删片 | 仅以服务端成功为准；本地审计 |
| 短信（后期） | 验证码短 TTL、频控、防刷；通道密钥仅存服务端 |

### 7.3 网络策略

| 策略 | 首期 |
|------|------|
| 自动上传 | 仅 Wi‑Fi |
| 访问入口 | 统一公网域名（云服务器 → FRP → iMac） |
| 蜂窝 | 默认不上传；浏览是否允许蜂窝下载可配置（默认允许缩略图） |

## 8. 技术选型建议（首期）

| 层级 | 建议 | 说明 |
|------|------|------|
| iOS App | Swift + SwiftUI | Photos、BackgroundTasks、URLSession、Network |

| H5 | Vite + React 或 Vue | 与 Server 同仓 `web/`，可由 Server 托管 |
| iMac 进程 | Docker Compose 或 launchd | 数据目录挂载外盘 |
| 网关 | 已有 FRP + 云服务器 Nginx/Caddy | 业务不迁云 |

## 12. 成功标准

1. 多用户可分别注册登录，彼此媒体默认互不可见  
2. Wi‑Fi 下新增照片可自动上传到**当前用户**库，无需手动点上传  
3. 服务端校验成功后，本机对应原片被删除，手机空间下降  
4. 原片删除后，App 仍可浏览缩略图并按需看大图  
5. 朋友凭分享链接可在 H5 浏览指定内容，无法访问未分享内容  
6. 原片只落在家中 iMac；云服务器仅作 FRP/反代入口
